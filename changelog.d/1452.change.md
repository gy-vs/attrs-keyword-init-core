The merge rules for class-level and field-level `kw_only` now match `dataclasses`: a class-level `kw_only` (for example, `attrs.define(kw_only=True)`) is only the default for the class's *own* fields that don't set `kw_only` explicitly.
A field-level `kw_only=True` or `kw_only=False` always takes precedence, and a subclass's `kw_only` no longer changes how fields inherited from base classes are passed.
Accordingly, `attrs.field()`'s and `attr.ib()`'s `kw_only` parameter now defaults to `None`, meaning "use the class-level setting".

The historic behavior -- where a class-level `kw_only=True` forcibly converted *all* fields, including inherited ones and explicit `kw_only=False` ones -- can be restored using the new `attrs.set_kw_only_override()` switch, and only applies while it is enabled.
